- **Source:** `https://github.com/NuvioMedia/NuvioMobile/pull/1941`
- **Base Commit / Ref:** `refs/pull/1941/head` (`7c4be289`)
- **License:** GPL-3.0 (Part of NuvioMobile)

  - `composeApp/src/commonMain/composeResources/values-zh-rTW/strings.xml`

### Technical Findings & Evaluation
- **String Coverage:** 2,241 out of 2,249 base strings in `values/strings.xml` (99.6% complete).
- **Format Integrity:** 100% placeholder accuracy (0 formatting mismatches).
- **Plurals:** Correctly defines 3 plurals (`cw_airs_in_days`, `cw_airs_in_days_short`, `entity_browse_title_count`).
- **Defects & Areas for Improvement:**
  1. **8 Missing Upstream Strings:**
     - `player_seek_position`: "Seek %1$s" -> "跳转至 %1$s"
     - `profile_already_active`: "Profile is already active" -> "个人资料已处于活跃状态"
     - `settings_stream_background_description`: "Choose whether to display artwork or a solid dark background on the streams screen." -> "选择在流媒体源页面显示背景海报或纯色深色背景。"
     - `settings_stream_background_title`: "Background" -> "背景"
     - `settings_tracking_anime_id_tvdb`: "TVDB (Preferred)" -> "TVDB（首选）"
     - `settings_tracking_anime_id_tvdb_description`: "Resolves anime IDs using TVDB mappings via Simkl." -> "通过 Simkl 使用 TVDB 映射解析动漫 ID。"
     - `trailer_enter_fullscreen`: "Enter fullscreen" -> "进入全屏"
     - `trailer_exit_fullscreen`: "Exit fullscreen" -> "退出全屏"
  2. **Taiwanese Phrasing in Simplified Chinese:**
     - `values-zh-rCN` was partially generated by character conversion rather than Mainland software localization:
       - "自订" -> "自定义"
       - "快取" -> "缓存"
       - "网页面板" -> "Web 控制台"
       - "汇入" -> "导入"
       - "汇出" -> "导出"
       - "专案" -> "项目"
       - "储存" -> "保存"
       - "附加元件" -> "插件 / 扩展"
       - "资料" -> "数据 / 信息"
       - "设定" -> "设置"
  3. **Locale Aliasing Conflict:**
     - `values-zh` contains Traditional Chinese identical to `values-zh-rTW`. Under JetBrains Compose Resources fallback, an unregioned `zh` locale defaults to Traditional Chinese. For `develop/cn-emby`, `values-zh` must default to Simplified Chinese (`zh-Hans` / `zh-CN`).
  4. **Upstream Contributor Requirements:**
     - Upstream maintainers require running Compose Multiplatform resource generation (`generateComposeResClass`) and locale validation tests. Simply cherry-picking the raw XML files without rebuilding resource classes causes build inconsistencies.
- **Verdict:** **USE WITH FIXES**.
  - **Explicit Policy:** Simply cherry-picking PR #1941 directly into the tree and treating localization as complete is **strictly prohibited**.
  - Phase 1 must import the baseline, add missing keys, normalize terminology to Mainland China software conventions, ensure `values-zh` defaults to Simplified Chinese, and rerun resource generation and test suites.

## 3. Plozz (`thatcube/Plozz`)

- **Source:** `https://github.com/thatcube/Plozz`
- **License:** GPL-3.0 with Apple App Store Exception
- **Audited Commit:** Latest HEAD (`main`)
- **Technology Stack:** Swift, SwiftUI, Swift Package Manager, iOS/tvOS/macOS Native.

### Architectural Insights for Nuvio
1. **Provider Abstraction Architecture:**
   - Plozz isolates media servers via dedicated Swift modules: `ProviderJellyfin`, `ProviderPlex`, `FeatureLiveTVCore`.
   - All providers conform to unified interfaces: `MediaProvider`, `MediaBrowseService`, `MediaAuthService`.
   - **Lesson for Nuvio:** In Kotlin Multiplatform, implement `EmbyApiClient` and `EmbyStreamRepository` behind an abstract `MediaSourceProvider` interface so Jellyfin and Plex can be added in the future without changing `StreamsRepository` or `PlayerEngine`.
2. **Credential Vault & Secure Storage:**
   - Plozz uses `MediaCredentialVault` backed by Apple Keychain (`kSecClassGenericPassword`, `kSecAttrAccessibleAfterFirstUnlock`).
   - Token mutations are logged in an append-only in-memory journal to prevent race conditions during background sync.
   - **Lesson for Nuvio:** Replaces plain `NSUserDefaults` with a minimal `Security.framework` Keychain wrapper on iOS and `EncryptedSharedPreferences` on Android.
3. **Multi-Server Aggregation:**
   - Plozz supports multiple simultaneous server connections by tagging items with a `CrossServerIdentity(serverId, itemId)`.
   - **Lesson for Nuvio:** Model `EmbyServerConfig` with a unique `serverId` to support future multi-server environments.

## 4. Labstream (`jlipworth/Labstream`)

- **Source:** `https://github.com/jlipworth/Labstream`
- **License:** GPL-3.0
- **Audited Commit:** Latest HEAD (`main`)
- **Technology Stack:** Swift, SwiftUI, AVFoundation / Custom Video Pipeline, tvOS/iOS/macOS.

### Deep Technical Insights on Emby API & Playback
1. **PlaybackInfo Negotiation Protocol:**
   - **Emby Divergence Identified:** Emby requires `UserId` in **BOTH** query parameters and the POST request body (`/Items/{itemId}/PlaybackInfo?UserId={userId}`). Omitting `UserId` from either query or body causes 401 or unexpected transcode fallback on certain Emby server versions.
   - **Encoder Leak Prevention:** Calling `PlaybackInfo` with transcode parameters on an Emby server immediately spins up an active ffmpeg transcoding job. If the client decides to Direct Play or cancel, it MUST issue `DELETE /Videos/ActiveEncodings?PlaySessionId={sessionId}` to release server CPU resources.
   - **PlaySessionId Persistence:** The `PlaySessionId` minted by `PlaybackInfo` must accompany all subsequent playback, stream URL, and session progress requests (`/Sessions/Playing`, `/Sessions/Playing/Progress`, `/Sessions/Playing/Stopped`).
2. **DeviceProfile Construction:**
   - Labstream constructs an explicit `DeviceProfile` detailing DirectPlay profiles (containers, audio/video codecs), DirectStream profiles, and SubtitleProfiles.
   - **Lesson for Nuvio:** Nuvio must introduce `EmbyDeviceProfileBuilder` in Phase 6. Rather than claiming universal format support, the profile must be conservatively tuned to empirically verified iOS MPV capabilities.

## 5. nuvio-sync (`dakotadawolfe/nuvio-sync`)

- **Source:** `https://github.com/dakotadawolfe/nuvio-sync`
- **License:** GPL-3.0
- **Audited File:** `addon/lib/embyStreams.ts`
- **Technology Stack:** TypeScript / Node.js (Stremio/Nuvio Addon server).

### Matching & Stream Resolution Analysis
1. **Matching via `AnyProviderIdEquals`:**
   - nuvio-sync queries Emby via:
     ```http
     GET /Users/{userId}/Items?IncludeItemTypes={Movie|Series}&Recursive=true&AnyProviderIdEquals=imdb.{imdbId}&Limit=1&Fields=ProviderIds,RunTimeTicks,Size,FileName,MediaStreams,Container,Bitrate,MediaSources,Path
     ```
   - Matches:
     - `imdb.tt1234567`
     - `tmdb.12345`
     - `tvdb.12345`
   - For TV Series Episodes:
     ```http
     GET /Shows/{seriesId}/Episodes?UserId={userId}&Fields=...
     ```
     Filters results where `ParentIndexNumber == season && IndexNumber == episode`.
2. **Direct Play Stream URL Generation:**
   - Format:
     ```
     {serverUrl}/Videos/{itemId}/stream.{container}?Static=true&mediaSourceId={mediaSourceId}&playSessionId={playSessionId}&api_key={accessToken}
     ```
3. **Scoring Candidates:**
   - nuvio-sync scores candidate media sources based on `SupportsDirectPlay`, `Protocol == "file"`, `Bitrate`, and container type.
   - **Lesson for Nuvio:** Nuvio can adopt this exact matching and URL resolution strategy directly in native Kotlin within `EmbyMatcher.kt` and `EmbyPlaybackResolver.kt`.
